# 0010. 스캔 문항번호 재현율: 이탤릭 두 자리, 위쪽 여백, 1개 번호 페이지

## Context
0009 적용 후 스캔에서 번호를 놓치는 페이지가 있었다(영어 p7 4→3, p2 9→7). 놓친 문항은 앞 문항에 붙었다. 반대로 "[31~34]"의 숫자나 국어 산문 줄머리의 자모 조각은 번호로 잡혔다. 페이지별로 비교하면 재현율은 264/270, 오검출은 30개였다.
원인은 다음과 같다.
1. 굵은 이탤릭 두 자리 번호에서 앞 숫자가 뒤 숫자와 겹쳐(-4px) 맨 왼쪽 숫자를 찾지 못했다. 그래서 여백 기준 들여쓰기(0007)에서 탈락했다(`segment.py:3555`).
2. 두 숫자가 붙은 덩어리는 면적이 320px을 넘어 숫자 후보에서 빠졌다(3460).
3. 번호가 하나뿐인 페이지(긴 지문 뒤 1문항)는 `_segment_visual_problem_markers`의 `marker_count < 2` 조건(4231) 때문에 전체가 무번호 단으로 처리됐다.
4. "[31~34]"의 "~"나 자모 획이 점 역할을 했다. 이들은 기준선보다 위에 있다.

## Decision
- 맨 왼쪽 숫자를 찾을 때 -6px 겹침까지 허용한다(3555).
- 폭 28px 넘게 붙은 숫자 덩어리는 면적 420px까지 허용한다(3460).
- 스캔 크기(숫자 높이 18px 이상)에서는 점의 아래끝이 숫자 아래끝보다 2px 넘게 높으면 안 된다(3518).
- 문항 시작 위쪽 여백 검사 `_starts_after_white_space`(4029, 4087):
  - 단의 보통 줄 간격(빈 행 연속 길이의 중앙값) × 1.35보다 큰 빈 띠가 번호 위에 있어야 한다.
  - 번호 바로 위에 묶음 지시문이 최대 3줄 붙어 있어도 된다. 밑줄·꼬리 행은 4행까지 건너뛴다.
  - 박스 테두리나 구분선 바로 아래는 통과다. 페이지 상단 10%는 검사하지 않는다.
- 스캔 PDF는 번호 1개로도 문항 분할을 한다(`min_markers=1`, 5286). 이미지 업로드는 지금처럼 2개가 기준이다.

## Consequences
- 페이지별 번호 재현율 264/270 → 268/270, 오검출 30 → 7.
- 스캔 단위 수: 영어 48/47/48(텍스트 48), 국어 57/58/58.
- 국어 텍스트 PDF 단위 수(59/67/61)에는 텍스트 기반 지문 조각이 포함되므로 직접 비교할 수 없다.
- 남은 오검출은 국어 1쪽 "제1교시" 상자(머리말 구분선이 상단 8%보다 아래에 있음)와 6월 고2 영어 p4다.
