# EDB Maker 0.2.13 내부 빌드 검증

2026-10-30 · 검증 소스 [`139d0a7`](https://github.com/Muuuuoouuun/edb_make/commit/139d0a756cfc19986280182a955c47e8a69538f0)

검증용 로컬 피드와 임시 PIN을 사용해 실제 설치 파일을 내려받고 앱을 교체·재시작했다. Windows는 이번 소스로 만든 **수정된 0.2.9 시험용 bootstrap → 0.2.13**, 두 Mac은 **원본 0.2.8 → 0.2.13**을 검증했다. Windows 결과를 원본 0.2.8에서의 직접 업데이트 성공으로 해석할 수 없다.

- 잘못된 PIN은 설치 파일 다운로드나 앱 종료 없이 거부했다.
- 올바른 PIN과 확인한 버전 정보로 설치하고 새 프로세스가 정상 실행됐다.
- 설정·활성 세션·작업 파일 9개를 보존했고 업데이트 전후 PDF→EDB 변환이 성공했다.
- 확인 후 업데이트 정보가 바뀐 경우 다운로드나 앱 종료 없이 거부했다.
- Windows 포터블·설치본 실행, 실제 재설치·제거 후 사용자 작업 파일 보존도 통과했다.

이 결과는 **네이티브 업데이트 API·설치기 검증**이다. 브라우저에서 업데이트 버튼을 클릭한 새 실험 결과로 보고하지 않는다. [UI 코드 확인](https://github.com/Muuuuoouuun/edb_make/blob/139d0a756cfc19986280182a955c47e8a69538f0/ui_prototype/app.jsx#L17850)상 업데이트 버튼은 설정 창을 열고 새 버전을 조회하며, 실제 설치에는 별도 확인과 PIN이 필요하다.

원본 Windows 0.2.4 설치 파일에는 HTTPS 업데이트 피드·다운로드 주소가 들어 있었지만 **PIN과 기본 PIN은 없었다**. 이번 내부 0.2.13에는 피드·다운로드 주소·PIN이 모두 설정되지 않았다. 따라서 **현재 고객이 업데이트 버튼만 눌러 새 내부 빌드로 자동 재설치되는 상태는 아니다.** 운영 배포 주소나 고객 설정을 이번 검증에서 변경하지 않았다.

Windows 설치 파일은 서명이 없으며 EXE 인증서 테이블도 비어 있음을 확인했다. Mac은 ad-hoc 서명이고 Apple 공증은 받지 않았다. 실제 ClassIn 프로그램의 GUI에서 열기나 고객 실물 PC 검증은 이 보고서 범위에 포함하지 않는다. 국어·영어 자료 품질 점수는 별도의 Linux 자료 평가 결과로 보고한다.

메타데이터를 다운로드해 다시 검사하면서 Actions 업로드가 숨김 정리 표식 `.edb-release-metadata-output`만 누락한 것을 확인했다. **원본 ZIP·추출 파일은 그대로 보존**했다. 별도 사본에서 정확한 생산 소스의 고정 표식만 복원했고, 원래 manifest의 크기·SHA256과 일치할 때만 허용했다. 그 밖의 파일과 설치 파일 바이트는 모두 동일하며 정규화 사본의 전체 메타데이터 검증이 통과했다. 복원 표식은 원래 다운로드 파일이나 실행 검증 증거로 취급하지 않는다.

후속 워크플로 수정 `ce4ac79`는 두 설치 파일 artifact의 명시적 업로드 경로 안에서 숨김 파일을 포함한다. 전체 빌드 디렉터리는 포함하지 않는다. 관련 **22개 테스트·33개 하위 테스트**를 통과했으며 앱 코드·설치 파일은 변경하지 않아 추가 네이티브 재빌드는 필요하지 않다.
