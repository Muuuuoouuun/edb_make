## 적용 사항

- OCR 구조화 출력에서 `text`와 중복되던 `lines` 배열을 제거하고 줄 정보를 로컬에서 재구성한다.
- OCR 프롬프트와 JSON 스키마를 핵심 전사 규칙만 남긴 compact 버전으로 고정한다.
- Gemini 3.5 Flash OCR은 `minimal` 사고 수준을 사용하고, 비상용 3.6 폴백은 안정성을 위해 `low`와 상세 계약을 사용한다.
- 페이지 보정은 일반 호출에서 advisory `problem_units`와 자유형 `notes`를 요청하지 않는다.
- 페이지 보정 블록은 짧은 키와 좌표 배열을 사용하며 OCR 본문과 OCR 줄 배열을 중복 전송하지 않는다.
- 페이지 보정 이미지의 긴 변을 2,048px로 제한하고 JPEG 품질을 78로 조정한다.
- 블록 수와 복잡도에 맞춰 구조화 출력 상한을 동적으로 계산한다.
- 실행 결과에 전체·단계별·모델별 토큰 효율 지표를 기록한다.

## 해석 가드레일

- OCR은 합성 시험지 4건, 페이지 보정은 합성 1페이지를 사용한 소규모 실측이다.
- 토큰 절감률을 운영 환경 예측치로 사용하기 전에 익명화된 실제 문서 코퍼스로 재검증해야 한다.
- 캐시 적중 호출은 이미 provider 토큰을 사용하지 않으므로 본 비교에서 제외했다.
