## 무엇을 고쳤나
실제 모의고사 PDF(텍스트 PDF와 스캔본)를 ClassIn EDB 문항 보드로 만들 때 다음 문제가 있었다. 박스 문항이 잘렸고, 지문 조각이 섞였고, 2단 읽기 순서가 틀렸고, 내용이 누락됐고, 스캔본은 과분할되거나 번호를 놓쳤다.

| 영역 | 주요 변경 | ADR |
|---|---|---|
| 전처리 | 기울기 보정을 minAreaRect에서 투영 프로파일(±5°)로 교체 | 0006 |
| 단 분리 | 중앙 세로선 우선, 없으면 가장 넓은 골짜기. 단 왼쪽 경계는 세로선·머리말을 무시하고 텍스트 여백으로 맞춤 | 0002, 0011 |
| 문항/지문 | 지문 시작에서 문항 crop을 자름. 국어 지문 헤더 정규식 확장("다음을 읽고", "(가)와 (나)를"). 뒤 번호보다 들여쓴 번호 목록은 중첩으로 처리 | 0003, 0004, 0008 |
| 누락 복구 | 어느 crop에도 속하지 않은 잉크를 복구하고 검토 플래그를 단다. 머리말 절반과 머리말 구분선 위는 제외. 묶음 지시문은 다음 문항에 포함. 같은 단의 연속 조각은 합침 | 0005 |
| 스캔 PDF | 텍스트 레이어가 없으면 시각적 번호 검출. 밀도 게이트, 여백 기준 들여쓰기, 마침표 모양(기준선의 꽉 찬 점, 뒤 띄어쓰기), 위쪽 여백 검사. 무번호 페이지는 단당 블록 1개. 1번호 페이지 허용. 머리말(상자 테두리와 구분)과 꼬리말 제외 | 0001, 0007, 0009, 0010, 0011 |

## 위험
- 스캔 휴리스틱의 기준값(머리말 13%, 구분선 30px, 1.8배, 줄 간격 ×1.35 등)은 200dpi 국어·영어 6종에 맞춰 정했다. 다른 해상도, 과목, 양식에서는 검증하지 않았다.
- 이미지 업로드 경로도 `_dark_numeric_problem_marker_component_offsets`를 공유한다. 기존 합성 테스트는 통과하지만 실사진 회귀는 확인하지 않았다.
- 복구 영역과 무번호 단 블록에는 review flag가 붙어 검토 UI에 더 많이 표시될 수 있다.
- 텍스트 PDF는 단 경계가 base보다 넓다(본문 잘림 방지). crop 크기가 소폭 달라진다.

## 남은 문제
- 국어 스캔은 텍스트 레이어가 없어 지문과 문항을 나누지 못한다. 그래서 단위 수(56~58)가 텍스트 PDF(59~67)보다 적다.
- 박스 안의 들여쓴 목록만 있는 단에서 여백을 오인할 위험은 남아 있다. 실제 시험지에서는 재현되지 않았다.
- 수학·탐구 등 다른 과목은 검증 범위 밖이다.
