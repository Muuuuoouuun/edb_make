# 로컬 EDB 기능 점검 · 2026-10-04

웹 체험 서비스(`trial_*`, `public`, `reports_worker`)를 제외하고 입력부터 ClassIn EDB 내보내기까지 점검했다. 세 서브에이전트가 인식, 내보내기, 로컬 서버를 나눠 검토했고, 주 에이전트가 설정·캐시·이미지 보정·통합 검증을 담당했다. 수정한 코드는 담당자 외 에이전트가 교차 검토했다.

## 확인하고 수정한 문제

| 영역 | 재현된 문제와 영향 | 변경 |
| --- | --- | --- |
| 문항 보드 CLI | 직접 단일 EDB를 저장해 50페이지 제한을 우회했다. 합성 90페이지 PDF에서는 헤더 195페이지, 마지막 자료 끝 196.693페이지가 되어 끝부분 잘림 가능성이 있었다. | 기존 안전 분할 저장기를 사용한다. 반환값·요약·세션·핸드오프에 모든 파트를 반영한다. |
| CLI 재실행 | 같은 출력 폴더에서 단일 파일 → 분할 파일로 바뀌면 이전 단일 EDB가 남아 예전 자료를 열게 됐다. | 문항·페이지 CLI 모두 이전 실행 요약/세션으로 소유가 확인된 오래된 결과만 성공 후 보관 폴더로 이동한다. 배치 전체 입력이 다르거나 제작·저장이 실패하면 이전 파일을 보존한다. |
| 페이지 전체 EDB | 구형 페이지 모드는 26장부터 헤더를 52페이지 이상으로 늘려 파일 제한을 넘었다. | 헤더를 50페이지로 유지하고 42장부터 파일당 최대 41개 레코드로 균등 분할한다. 파트별 좌표를 다시 시작하고 API·세션·배치 계획·CLI에 모든 파일 정보를 전달한다. |
| 구형 구조화 EDB | `page_count_hint=25`인데 헤더는 50으로 저장되어 좌표와 실제 캔버스 높이가 달랐다. 그림·표·빈 본문에서 이미지 레코드와 헤더 유형도 달랐다. | 헤더·좌표·배치 계획에 같은 페이지 수를 적용하고 실제 레코드 유형으로 헤더를 결정한다. |
| 연속 배치 | 페이지 전체 이어붙이기에서 지정한 양수 간격이 무시됐다. | 배치 계획과 v1/v2 이미지 레코드에 명시 간격을 동일하게 반영한다. |
| 사진 입력 | 휴대폰 사진의 EXIF 방향을 무시했다. 추가 전처리를 끈 경우에도 잘못된 방향을 그대로 사용했다. | 회전·반전을 적용하고 방향 정보가 있는 사진은 정규화한다. 이미지 캐시 버전은 2로 올렸다. |
| HWP 입력 캐시 | 같은 이름의 문서 A → 수정본 B → A 복원 시 A의 캐시 메타데이터가 B가 덮어쓴 이미지를 가리켰다. | 원문 해시와 변환 옵션별 디렉터리에서 렌더링·변환·정규화한다. HWP 캐시 버전은 6으로 올렸다. |
| AI 교정 캐시 | 블록 유형·제목을 변경한 뒤 캐시키를 계산해 동일 입력의 다음 실행에서 다시 호출했다. | 교정 적용 전에 원래 입력 기준으로 캐시를 저장한다. mock 제공자 호출이 2회에서 1회로 줄어드는 회귀 검사를 추가했다. |
| AI 응답 처리 | ID 목록에 배열·객체가 섞이거나 제목·메모 유형이 틀리면 TypeError로 인식이 중단됐다. | 응답 구조를 먼저 검사하고 잘못된 응답에서는 기존 로컬 결과를 유지한다. |
| 수동 자르기 | 음수 좌표를 먼저 보정해 선택한 영역보다 오른쪽·아래쪽을 더 잘랐다. | 원래 선택 영역과 페이지의 교집합을 사용한다. 페이지 밖·NaN·무한대 좌표를 거부한다. |
| 문항 합치기 | 중복 ID 때문에 한 문항을 자기 자신과 합치거나 합친 문항 수를 잘못 표시했다. | 서로 다른 ID로 정규화한 뒤 최소 개수와 제목을 계산한다. |
| 로컬 API 요청 | 배열·null·문자열 JSON과 잘못된 UTF-8 요청이 응답 없이 예외 종료될 수 있었다. | 공통 요청 파서가 JSON 객체와 UTF-8을 검증해 HTTP 400으로 응답한다. |
| 설정 읽기 | 손상된 JSON 유형·인코딩으로 설정 조회나 시작 시 예외가 발생했다. | 유효한 객체만 읽고 잘못된 파일은 기본 설정으로 처리한다. |
| 설정 저장 | 저장 실패 후에도 실행 중인 API 키가 바뀌었다. 직접 덮어쓰기는 저장 중 실패 시 기존 설정도 손상시킬 수 있었다. | 임시 비공개 파일에 쓰고 원자적으로 교체한다. 저장이 성공한 뒤 환경변수를 바꾸며 읽기·수정·저장을 잠금으로 묶는다. |
| OCR/AI 캐시 | 문법상 JSON이어도 내부 구조·수치가 잘못되면 인식 전체가 중단되거나 잘못된 값을 재사용했다. | 손상된 구조·UTF-8·비유한 수치를 캐시 미스로 처리한다. 다음 실행에서 정상 결과로 교체할 수 있다. |
| 투명 이미지 보정 | 이미 투명한 테두리에서 배경색을 흰색으로 추정해 흰 글씨를 전부 지웠다. | 테두리에 배경색 근거가 없으면 기존 알파를 보존한다. NumPy 없는 경로의 투명 픽셀 이중 집계도 바로잡았다. |
| Upscayl 결과 | 비율이 틀리거나 높이가 잘린 결과를 정상으로 적용했다. RGB 결과는 원본 투명 배경을 불투명하게 만들었다. | 이상한 크기·비율은 원본으로 복귀한다. RGB 결과에는 원본의 크기 조정된 알파를 복원한다. |

주요 변경 파일: `app_server.py`, `build_problem_board_edb.py`, `build_mvp_export.py`, `export_mvp_edb.py`, `placement_engine.py`, `preprocess.py`, `page_repair.py`, `user_settings.py`, `pipeline_cache.py`, `image_reconstruction_backend.py`, `upscayl_backend.py`.

## 검증

- 변경 전 기준 검사: 1,318 passed, 152 subtests passed.
- 추가된 회귀 검사는 손상된 저장 파일, 입력 경계, 이미지 보존, 동일 입력 재처리, 다중 EDB 분할과 문항 수 보존을 검사한다.
- 단일 → 분할 → 단일, 분할 개수 감소, 다른 원문·배치 입력, 잘못된 파일 목록, 제작 실패, 보관 실패를 검사했다. 이전 파일은 삭제하지 않고 보관하며, 임의 파일과 외부 경로는 변경하지 않는다.
- 실제 CLI 합성 PDF 검사: 26개 원본 페이지를 3개 EDB로 저장했다. 모든 헤더가 50페이지이며 26개 레코드를 보존했고 CLI·세션·핸드오프의 파트 개수가 일치했다.
- 임시 로컬 HTTP 서버에서 업로드 → 분할 → 중복 ID를 포함한 합치기 → 검수 확인 → 제작 계획 → EDB 제작·다운로드 → PNG ZIP 저장 → 서버 재시작 후 복원을 실행했다. EDB 다운로드는 디스크 파일과 바이트가 일치했고 ZIP 무결성도 통과했다.
- 잘못된 JSON·UTF-8 요청은 HTTP 400, 오래된 세션 버전으로 복원하는 요청은 HTTP 409와 `session_conflict`를 반환했다.
- 합성 품질 관측 데이터 평가기는 2개 사례, 0 gate failures로 통과했다. 이는 평가기 동작 검사이며 실제 시험지의 인식 정확도 측정값은 아니다.
- `pip check`, 선택 런타임 라이선스 검사, 변경 파일 컴파일, `git diff --check`를 실행했다.

코어 수정 완료 시점의 통합 검사: **1,378 passed, 188 subtests passed** (64.06초). 기준 검사보다 회귀 테스트 60개를 추가했다. 5개 SWIG 확장 모듈의 사용 중단 경고가 있었으며 테스트 실패는 없었다. Python 3.14.3 환경에서 다음 명령을 사용했다.

```sh
.venv/bin/python -m pytest -q \
  --ignore-glob='test_trial*.py' \
  --ignore=test_web_trial_operations_docs.py
```

페이지 전체 export의 추가 회귀 6개와 공유 보관 함수·문항 CLI 회귀 11개도 통과했다.

이후 우측 패널 위계, 미리보기, 편집 상태 보존과 혼합된 긴 자료의 실제 이미지 배치까지 점검했다. 최신 전체 검사는 **1,460 passed, 209 subtests passed** (70.66초), UI 367개와 패키징 74개가 통과했다. 실제 일괄 처리·실행 취소·제작·다운로드와 다섯 창 크기의 화면 검증 근거는 [Design QA 최신 재검증](../design-qa.md)에 기록했다.

## 검증 범위의 한계

실제 Gemini 요청과 GPU Upscayl 실행은 호출하지 않았다. 외부 응답·실행 실패·출력 형태는 mock으로 검증했다. HWP 캐시 회귀 검사는 합성 원문과 mock 변환기로 실행했다. 설치 프로그램을 다시 빌드하거나 배포하지 않았다.

ClassIn 앱은 설치되어 있으나 컴퓨터 사용 도구가 Mac 잠금 상태를 보고해 실제 화면에서 파일을 여는 검증은 진행하지 못했다. 기존 사용자 작업 데이터는 점검 입력으로 사용하거나 변경하지 않았다.

이미지와 HWP 캐시 버전이 변경되어 기존 캐시는 다음 처리 때 한 번 다시 생성된다. CLI가 보관한 이전 EDB는 출력 폴더의 `edb_archive`에서 복구할 수 있다.
