# Work 3: 국어·영어 PDF 구조/이미지 하이브리드 실험

## 1. 목적과 격리 원칙

Work 3의 의사결정은 “국어·영어 PDF에서 현재 이미지 중심 경로보다 PDF 구조 활용 경로가 품질을 유지하면서 더 빠르고 저렴한가?”이다.

- 프로덕션 `S2/S3` 처리 단계와 별개의 실험 트랙이다.
- 대상은 PDF 형식의 국어와 영어이며, 1차 비중은 국어 75%, 영어 25%로 둔다.
- 수학·과학·HWP·일반 이미지는 이번 실험에 포함하지 않는다.
- 기존 이미지 경로는 기준선이자 항상 가능한 fallback으로 유지한다.
- Work 3에서 합격하기 전에는 기존 기본 경로와 UI 설정을 변경하지 않는다.

## 2. 비교할 세 경로

| 경로 | 인식·배치 | 최종 표현 | 역할 |
|---|---|---|---|
| V0 이미지 기준선 | 200DPI 렌더링 후 이미지 분석 | 투명 PNG/EDB 이미지 | 현재 성능 기준 |
| V1 PDF 구조 우선 | 글자·span·block 좌표로 지문/단/순서 결정 | 필요한 좌표만 PDF에서 한 번 렌더링 | 텍스트 PDF 최적화 후보 |
| V2 페이지별 하이브리드 | 페이지별 텍스트 레이어 품질을 판정해 V1 또는 V0 선택 | 동일 | 실제 출시 후보 |

PDF 텍스트를 새 폰트로 다시 조판하는 완전 재구성은 1차 비교에서 제외한다. 자간, 줄바꿈, 수식, 특수문자 재현 위험이 커서 별도 실험 없이는 원문 보존 경로로 채택하지 않는다.

## 3. 테스트 데이터

### Pilot

- 총 8개 PDF, 최소 80페이지
- 국어 6개/60페이지, 영어 2개/20페이지
- 텍스트 PDF 50%, 텍스트+이미지 혼합 30%, 스캔 20%
- 각 유형에 1단, 2단, 다음 열 연결, 다음 페이지 연결, 표/삽화 포함 지문을 넣는다.

### 확대 검증

Pilot 합격 후 30개 PDF, 300페이지 이상으로 확대한다. 동일 시험지의 페이지만 늘리는 대신 서로 다른 발행처와 제작 방식을 포함한다.

### 정답 데이터

페이지별로 다음을 사람이 한 번 확정한다.

- 지문 그룹 ID와 대응 문항 범위
- 정규화된 본문 텍스트와 읽기 순서
- 좌우 단 및 페이지 연결 순서
- 본문 시작/끝 좌표
- 포함되면 안 되는 머리말, 페이지 번호, 배지
- 표·삽화·각주 포함 여부

## 4. 핵심 KPI와 합격선

품질은 가중 평균으로 속도와 교환하지 않고 먼저 통과해야 하는 gate로 사용한다. 목표값은 첫 Pilot 결과 전까지 잠정값이다.

### Primary KPI

1. **사용 가능 지문 성공률**
   - 계산: 누락·중복·순서 오류·경계 글자 잘림·레코드 겹침이 모두 없는 지문 그룹 / 전체 지문 그룹
   - 잠정 합격선: 국어 98% 이상, 영어 97% 이상
   - 치명 오류 guardrail: 잘못된 지문 병합과 EDB 레코드 겹침은 0건

2. **처리 시간**
   - 페이지별 `parse`, `render`, `OCR`, `stitch`, `encode` 시간을 따로 기록한다.
   - 판단값: 전체 작업 p50/p95 초/페이지와 문서 완료 시간
   - 잠정 합격선: 텍스트 PDF에서 V2 p95가 V0의 85% 이하, 전체 데이터에서는 V0의 115% 이하

3. **100페이지당 총비용**
   - 계산: 로컬 실행 시간 비용 + 외부 API 비용 + 수동 검수 시간 비용
   - `로컬 비용 = 실행 초 / 3600 × 장비 시간당 비용`
   - `검수 비용 = 검수 분 / 60 × 검수자 시간당 비용`
   - 잠정 합격선: V2가 V0보다 총비용 20% 이상 절감하거나, 동일 비용에서 성공률을 2%p 이상 개선

### Driver metrics

- 구조 활용 가능 페이지 비율: `pdf-structure` 판정 페이지 / 전체 페이지
- OCR fallback 비율: OCR 페이지 / 전체 페이지
- 글자 recall: 정답 텍스트 글자 중 순서까지 맞게 복원된 글자 비율
- 수동 검수 시간: 문서당 실제 수정·확인 분

### Quality guardrails

- 원문 대비 글자 recall 99.5% 이상(텍스트 레이어 정상 페이지)
- 사용자 관점 시각 점수 95/100 이상
- 우측/좌측 경계 글자 누락 0건
- 배경·머리말·페이지 배지 혼입 0건
- 레코드 겹침 0건, 명시 간격 유지
- API 오류가 있어도 이미지 fallback으로 문서 생성 가능

## 5. 측정 절차

1. 같은 기기, 같은 PDF, 같은 EDB 설정으로 V0/V1/V2를 각각 3회 실행한다.
2. 첫 실행과 warm-cache 실행을 분리한다.
3. 중앙값을 대표값으로 쓰고 p95를 병목 판단에 사용한다.
4. 자동 평가는 글자 recall, 그룹 정확도, 좌표 초과/누락, 레코드 겹침을 측정한다.
5. 육안 평가는 경로 정보를 가린 상태에서 2명이 5개 항목을 각 20점으로 평가한다.
6. 오류는 `누락`, `잘못된 병합`, `읽기 순서`, `경계 잘림`, `불필요한 요소`, `시각 품질`로 분류한다.

## 6. 단계별 진행

### W3-0: PDF 적합성 프로브

`scripts/work3_pdf_probe.py`로 글자 수, 텍스트 영역 비율, 이미지 블록, PDF 파싱 시간, DPI별 렌더링 시간/용량을 기록한다. 이 단계는 외부 API를 호출하지 않는다.

```bash
.venv/bin/python scripts/work3_pdf_probe.py sample.pdf \
  --subject korean \
  --render-dpis 144,200,300 \
  --output /tmp/work3-probe.json
```

### W3-1: 구조 기반 지문 범위

- `rawdict`의 char bbox를 사용해 실제 글자 끝 좌표를 계산한다.
- 문항 범위 표지, 단 경계, 읽기 순서를 텍스트 좌표로 결정한다.
- 결과 텍스트와 정답 데이터를 비교하되 최종 이미지는 만들지 않는다.

현재 첫 비교 도구는 생산 지문 검출 결과를 고정한 뒤 전체 페이지 렌더 후 crop(V0)과 동일 PDF clip 직접 렌더(V1)를 비교한다. 이로써 검출 알고리즘 차이와 렌더링 방식 차이를 섞지 않고 속도·픽셀 보존 효과를 먼저 측정한다.

```bash
.venv/bin/python scripts/work3_compare_pdf_paths.py sample.pdf \
  --subject korean \
  --dpi 200 \
  --output-dir /tmp/work3-path-comparison
```

### W3-2: 단일 렌더링과 EDB 배치

- 확정된 PDF clip을 목표 해상도로 한 번만 렌더링한다.
- 중간 확대/축소를 제거한다.
- 기존 투명 백묵 처리와 20px 비겹침 규칙을 그대로 적용한다.

### W3-3: 페이지별 자동 라우팅

- 텍스트 레이어 정상: V1
- 일부 글자/이미지 혼합: 텍스트 좌표 + 이미지 보완
- 텍스트 없음: V0 + OCR
- 결과에 선택 경로와 fallback 이유를 기록한다.

## 7. 채택 규칙

- V1은 텍스트 PDF 전용 최적화로만 채택할 수 있다.
- 전체 기본 후보는 V2이며, 모든 품질 guardrail을 통과해야 한다.
- 품질이 같으면 총비용이 낮은 경로를 선택한다.
- 총비용이 비슷하면 p95 처리 시간이 낮은 경로를 선택한다.
- 검수 시간까지 포함해 이점이 없으면 기존 V0를 유지한다.

## 8. 현재 확인 가능한 증거와 남은 입력

- 현재 파이프라인은 PDF 렌더링과 텍스트 block 추출을 모두 지원한다.
- 국어 실제 사례에서는 PDF block 경계만으로 열 경계 글자가 빠지는 사례가 있어 char bbox 검증이 필요하다.
- Pilot의 확정 비용 비교에는 장비 시간당 비용, OCR/API 단가, 검수자 시간당 비용이 필요하다.
- 영어 실물 PDF와 스캔형 국어 PDF가 추가되어야 데이터 구성이 완성된다.

## 9. 2026-07-16 첫 적합성 프로브

대상은 이번 개선에 사용한 2026년 6월 고2 국어 PDF 16쪽이다. 동일 실행에서 144/200/300DPI를 순차 렌더링했으므로 전체 실행 시간은 각 DPI의 단독 처리 시간이 아니라 비교 측정 전체 시간이다.

| 항목 | 결과 |
|---|---:|
| 구조 활용 가능 페이지 | 16/16 (100%) |
| 예상 OCR 페이지 | 0쪽 |
| 외부 API 비용 | $0 |
| 텍스트 좌표 파싱 중앙값 | 0.0076초/쪽 |
| 144DPI 렌더 중앙값 | 0.0714초/쪽, PNG 약 0.73MB/쪽 |
| 200DPI 렌더 중앙값 | 0.1239초/쪽, PNG 약 1.11MB/쪽 |
| 300DPI 렌더 중앙값 | 0.2621초/쪽, PNG 약 1.85MB/쪽 |

이 결과는 해당 PDF가 V1/V2 실험에 적합하다는 근거다. 지문 그룹 정확도, char recall, EDB 시각 품질을 아직 V0와 직접 비교하지 않았으므로 구조 우선 경로가 최종적으로 더 우수하다는 결론은 아니다.

## 10. V0/V1 동일 좌표 렌더 비교

동일 국어 PDF의 11개 지문 그룹(15개 단 조각)을 200DPI에서 3회 비교했다. 지문 검출과 연결 정돈은 공통으로 고정하고 렌더 방식만 바꿨다.

| 항목 | V0 전체 페이지 후 crop | V1 PDF clip 직접 렌더 |
|---|---:|---:|
| 렌더 시간 중앙값 | 0.1670초 | 0.0842초 |
| 공통 검출 포함 end-to-end 중앙값 | 1.2037초 | 1.1219초 |
| 결과 PNG 총량 | 약 8.24MB | 약 8.24MB |
| 최소 픽셀 유사도 | 기준 | 100% |
| 최소 글자 획 F1 | 기준 | 100% |

- 직접 clip 렌더 구간은 중앙값 기준 약 1.98배 빨랐다.
- 공통 지문 검출이 전체 시간 대부분을 차지해 end-to-end 개선은 약 1.075배, 시간 절감률로는 약 6.8%였다.
- 11개 지문의 크기와 픽셀은 모두 일치했고, `11~15`, `16~19` 연결부도 육안으로 동일했다.
- 본문 char bbox 포함률은 100%, clip 밖으로 잘린 본문 글자는 0자였다.
- 기존 passage block 경계 밖의 본문 138자를 안전 여백으로 포함했고, 글자와 수평 clip 경계의 최소 거리는 22.6px였다.
- 외부 API 호출과 비용은 두 경로 모두 0이었다.

따라서 직접 clip은 품질 손실 없는 안전한 최적화 후보지만, 이것만으로는 잠정 목표인 텍스트 PDF end-to-end 15% 단축에 도달하지 못한다. 다음 성능 레버는 공통 지문 검출/페이지 준비 시간이며, 다음 품질 레버는 block 경계가 아닌 char bbox 기반 경계 검증이다.
