# 미리보기 배치 요약 바 개선 기획

작성일: 2026-10-06
범위: 칠판 바로 위 배치 요약 바와 연결된 상세 정보·여백 조절. 이번 작업은 기획이며 제품 코드는 변경하지 않는다.

## 목표

사용자가 전체 ClassIn 분량과 선택 문항 위치를 빠르게 읽고, 선택 문항을 조절할 때 칠판 화면 크기를 유지한다.

## 현재 확인한 문제

근거: 사용자가 제공한 바 스크린샷과 현재 BoardStage·board.css 구현.

1. 기본 바: 전체 페이지 수, 선택 범위, 다음 시작, EDB 파일 수, 여백 변경이 같은 줄에서 경쟁한다. 상태와 조작의 구분이 약하다.
2. 배치 정보: `자세히`의 내용이 불명확하다. 현재 구현은 상세를 펼치면 칠판 최대 너비 계산도 바꾸므로 상세 확인이 미리보기 축소로 이어진다. 이 동작은 코드로 확인했으며 이번 기획에서 직접 실행 검증하지 않았다.
3. 여백 조절: `여백 0.5p 삭제`가 어느 문항의 여백인지, 이후 문항도 이동하는지 바만 읽어서는 알기 어렵다. 내부 높이 단위 p는 ClassIn 한 쪽과 다르다.

좁은 스크린샷에서는 작은 배지 글자의 가독성이 떨어져 보인다. 실제 배율의 대비, 키보드 조작, 스크린리더 동작은 별도 검증이 필요하다. 카드 제목 또는 툴팁이 바와 칠판 사이에 겹쳐 보이는 문제도 구현 단계에서 재현한다.

## 권장 구성

기본 바는 한 줄을 유지한다. 왼쪽에 `ClassIn 전체 2쪽`, 이어서 낮은 강조의 `선택 1번 · 1–2쪽`, 오른쪽에 유일한 버튼 `배치 정보`를 둔다.

| 현재 항목 | 개선안 | 위치 |
| --- | --- | --- |
| 예상 ClassIn 2페이지 | ClassIn 전체 2쪽 | 기본 바의 주 정보 |
| 선택 01 C1–C2 | 선택 1번 · 1–2쪽 | 기본 바의 보조 정보 |
| 다음 C3 | 다음 문항 시작: 3쪽 | 배치 정보 상세; 마지막 문항이면 숨김 |
| EDB 예상 — | 계산 전에는 기본 바에서 생략 | 내보내기 요약; 계산 중·예상·확정·실패 구분 |
| 자세히 | 배치 정보 | 명시적인 상세 버튼 |
| 여백 0.5p 삭제 | 뒤 여백 줄이기 | 우측 선택 문항의 배치 편집 영역 |

페이지 수가 계산 중인 경우에만 `분량 계산 중`을 표시하고, 확정 여부를 설명하는 작은 도움말을 제공한다. 페이지 수는 내보내기 확정 결과와 구분한다. 숫자 표시 단계에서 빈 값과 계산 실패를 동일한 대시로 표현하지 않는다.

## 정보·조작 상세

### 배치 정보

바 아래에 겹쳐 열리는 작은 팝오버를 기본으로 한다. 칠판의 너비·높이·배율·스크롤은 유지한다. 보드 밖 가용 공간을 우선 사용하고 문항 본문을 최대한 가리지 않는다. 좁은 화면에서는 하단 시트를 사용한다.

내용은 선택 문항의 시작·끝·다음 실제 문항 위치, 전체 여백, 현재 간격 방식, 자동 축소 적용 여부로 한정한다. 사용률·내부 좌표·미리보기 화면 수 등 진단 수치는 추가 상세로 접는다. 현재 배율은 상단 확대·축소 도구와 중복 표시하지 않는다.

버튼에 열림 상태를 제공하고, Escape·바깥 클릭으로 닫으며 닫힌 뒤 버튼으로 초점을 돌린다. 숫자는 텍스트로도 읽을 수 있게 하고 색만으로 선택/경고를 구별하지 않는다.

### 뒤 여백 줄이기

우측 배치 편집에서 `선택 1번 뒤 여백`과 조절 효과를 함께 설명한다. 다열일 때에는 실제 적용 단위가 행이라는 점을 반영해 `선택 행 뒤 여백`으로 표시한다. 이미지 안의 흰 배경을 자르는 기능과 구분한다.

실행 전 도움말: `뒤 여백을 줄이고 이후 문항을 위로 당깁니다.`
실행 후 토스트: `뒤 여백을 줄였어요`와 `되돌리기`. 연속 실행으로 값을 복구할 수 없게 되지 않도록 적용 전 간격을 보존한다. 제거 가능한 여백이 없으면 작업 영역에서 그 상태를 설명하고, 기본 바에 버튼이 생겼다 사라지며 폭이 흔들리는 현상을 없앤다.

사용자 화면은 ClassIn `쪽` 단위를 우선 사용한다. 내부 p를 단순히 쪽으로 이름만 바꾸지 않는다. 예를 들어 내부 0.5p는 ClassIn 한 쪽=1.2p 기준 약 0.42쪽이다. 반올림된 값은 `약`을 붙이고 내부 정밀 값은 진단에 남긴다.

## 시각·반응형 규칙

- 기존 색상·폰트·라운드 토큰을 사용한다. 새 카드 디자인이나 전체 화면 재설계는 하지 않는다.
- 모든 정보를 알약 배지로 감싸지 않는다. 전체 분량은 굵은 텍스트, 선택 문항은 보조 텍스트, 조작은 버튼으로 구분한다.
- 데스크톱 기본 높이는 44–48px, 본문은 기존 13–14px 토큰 수준, 버튼 터치 영역은 44px을 목표로 한다.
- 좁은 화면에서는 `전체 2쪽`으로 줄이고 선택 범위 상세를 접는다. 칠판 가용 크기를 줄이는 추가 행은 만들지 않는다.
- 드래그 중 수치 업데이트가 레이아웃 이동이나 과도한 음성 알림을 만들지 않게 한다.

## 구현 우선순위

1. 기본 바에서 EDB·다음 시작을 걷어내고 문구·정보 강조를 정리한다.
2. 여백 조절을 선택 문항 배치 편집으로 옮기고 범위 설명·되돌리기를 추가한다.
3. 상세를 팝오버/시트로 전환해 칠판 크기 변경을 없앤다.
4. 툴팁 겹침, 좁은 화면, 계산 상태, 다열·다중 선택·마지막 문항 상태를 검증한다.

## 완료 기준

- 기본 바에서 전체 분량과 선택 문항 위치를 바로 읽을 수 있다.
- 상세 열기/닫기와 여백 상태 변화가 보드 크기·배율·스크롤을 바꾸지 않는다.
- 마지막 문항에 `다음 문항`이 있는 것처럼 표시하지 않는다.
- 계산 전 EDB 값과 내부 p 단위를 일반 작업 화면에 노출하지 않는다.
- 여백 조절이 이미지 자르기와 구분되고 이후 문항 이동·다열 적용 범위가 설명된다.
- 여백 변경 후 되돌리기와 다시 선택한 상태에서도 값이 정확하다.
- 기존 본문·제목줄 드래그와 선택 동작이 유지된다.
- 좁은 화면 및 키보드·스크린리더 흐름에서 잘림·초점 손실·반복 알림이 없다.

## 근거와 검증 범위

스크린샷의 기본 상태를 확인했고, 상세·여백 동작은 코드를 읽어 기획했다. 실제 사용자 세션에서 펼치기·여백 변경을 수행하거나 접근성 적합성을 검증한 보고서는 아니다.
