# 기본 Home UI 개발 기준

## 통합 기준

- 대상: Windows 개발 브랜치 `up2_win`.
- 가져온 브랜치: `origin/feat/home-ui-develop`, `7d1d6c6`.
- 기존 Windows 기준점: `60e488f`.
- 기본 Home UI와 이어지는 자료 준비 → 검수 → 칠판·내보내기 흐름을 개발 기준으로 사용한다.
- 프리미엄 상품, 결제, 업셀, 사용량 제한 변경은 이번 개발 범위에 포함하지 않는다. 함께 들어온 웹 체험 코드의 기존 정책은 변경하지 않는다.

## 작업할 화면과 코드

로컬 앱의 `/`는 `ui_prototype/index.html`을 통해 `/board.html`로 이동한다.
홈과 편집 화면은 `ui_prototype/app.jsx`, 디자인 토큰과 반응형 스타일은 `ui_prototype/board.css`에 있다.
`public/`의 웹 체험 화면은 별도 진입점이며 로컬 편집기의 Home UI와 혼동하지 않는다.

생성된 `ui_prototype/app.bundle.js`를 직접 편집하지 않는다. 소스를 수정한 뒤 아래 명령으로 번들과 캐시 식별자를 갱신한다.

```powershell
node scripts/build_frontend_bundle.mjs
node scripts/build_frontend_bundle.mjs --check
.venv\Scripts\python.exe scripts/verify_frontend_package.py
```

## 유지할 통합 동작

- 새 홈의 파일 추가, 샘플 진입, 최근 작업 복원, 업로드 방식 선택을 유지한다.
- 기존 Windows의 원문 문항 번호 편집, 본문 드래그, Alt+드래그 순서 이동, Esc 취소를 유지한다.
- 세로 이동 공간은 명시적인 추가 칸으로 저장하고, `1.2 맞춤`과 `빈틈 없이` 배치 양쪽에서 반영한다.
- 미리보기, 제작 전 검사(`publish_guard.js`), 서버의 제작 계획, 실제 EDB 출력에 같은 배치 값을 전달한다.
- Windows 경로 제한 대응, 복구·보고서 기능, 설정 파일 원자적 저장을 유지한다.
- 프런트엔드 소스는 `.gitattributes`의 LF 규칙을 지킨다. 운영체제별 줄바꿈 차이로 번들 해시가 달라지면 안 된다.

## 세 패널 정렬과 반응형 기준

- 자료 목록·칠판 도구 모음·우측 탭 제목줄은 `--panel-header-height`(48px)를 공유한다. 내용이 많은 검수 도구 모음은 줄바꿈을 허용하며 조작 버튼을 잘라내지 않는다.
- 넓은 화면은 좌측 220–248px, 우측 320–360px 범위로 제한하고 남은 폭을 칠판에 준다. 1280/1100/920px 구간에서는 측면 폭을 단계적으로 줄인다.
- 목록과 설정 본문은 각각 스크롤하고 스크롤바 공간을 예약한다. 칠판과 배치 요약은 상단부터 같은 폭으로 정렬한다.
- 900px 이하에서 빈 홈은 한 페이지로 스크롤한다. 자료가 있는 작업 화면은 목록·칠판·설정을 전환하되 컴포넌트를 유지해 입력 중인 값을 버리지 않는다.
- 패널 전환 버튼은 이름 있는 영역을 `aria-controls`로 연결한다. Alt+1/2/3은 우측 탭을 선택하면서 모바일 설정 패널도 연다. 입력창에서는 이 단축키를 가로채지 않고, 검수 편집기가 활성화된 동안 중앙 화면을 숨기지 않는다.
- 낮은 가로 화면에서는 배치 저장 상태와 두 작업 버튼을 한 줄에 배치해 설정 본문의 스크롤 공간을 확보한다.
- 변경은 로컬 기본 Home과 편집 화면의 배치·안내·탐색에 한정한다. 문제 인식, EDB 배치 값, 저장 형식, 프리미엄 정책은 변경하지 않는다.

## 페이지 경계와 좌측 목록의 정보 밀도

- 페이지 점선은 다음 ClassIn 쪽의 시작을 뜻한다. 누적 1.2p 위치에는 `ClassIn 2쪽 · 1.2p`, 2.4p 위치에는 `ClassIn 3쪽 · 2.4p`를 표시한다. 쪽 번호와 실제 점선 좌표, EDB 출력 계산은 바꾸지 않는다.
- 자료 카드의 네 조작 버튼은 메타정보 칸 안에서 줄바꿈하지 않고 카드 하단 전체 폭을 사용한다. 좁은 화면의 버튼은 44px 클릭 영역을 유지한다.
- 좌측 제목줄의 중복 아이콘 대신 기존 파일 추가 줄에 폴더+ 아이콘의 `파일 추가`와 겹친 문서+체크 아이콘의 `전체 보존`을 둔다. 전체 보존은 기존 처리 방식 지정 동작이며 AI 실행을 시작하지 않는다.

## 중앙 상단 바 통합 기획 — 제안, 미구현

현재 `실시간 칠판 미리보기·세션·배율` 도구 모음과 `ClassIn 전체·선택 쪽·배치 정보` 요약 카드는 같은 작업의 조회·조작이다. 하나의 도구 모음으로 합치는 안을 제안한다.

```text
[미리보기 · 세션]  [전체 2쪽 · 선택 1–2쪽 ▾]  [− 보기 100% +] [선택 맞춤]
```

- 넓은 화면: 세 영역을 한 줄, 기본 높이 48px로 유지한다. 부동 요약 카드(48px)와 뒤 간격(12px)을 없애면 칠판 시작 위치를 약 60px 위로 확보할 수 있다.
- 가운데 폭 640px 이하: 세션 이름은 툴팁으로 옮기고 `전체 2쪽 ▾`, `맞춤`으로 문구를 줄인다. 375px에서는 동일한 컨테이너 안에서 정보/배율을 두 줄로 재배치하며 버튼을 숨기지 않는다.
- 요약을 누르면 기존 배치 정보 팝오버를 재사용한다. 내부 높이, 여백, 열 수, 경고는 펼친 정보에 둔다. 키보드 열기·Esc 닫기·포커스 복귀를 유지한다.
- 하단 처리 상태 줄은 자료 처리 진행 정보이므로 이번 상단 통합과 구분한다. 중복 정보는 후속 검토한다.
- 구현 순서: 통합 도구 모음 생성 → 기존 요약 데이터를 연결 → 부동 카드 제거 및 미리보기 높이 계산 보정 → 배율·스크롤·위치 드래그·375/901/1024/1440px 회귀 검증.
- 영향: 화면 구조와 미리보기 가용 높이만 변경한다. 배치/내보내기 모델은 유지한다. 중앙 상단 통합은 이번 변경에 구현하지 않았으며 확정 후 진행한다.

## 변경 후 검증

```powershell
.venv\Scripts\python.exe -m pytest -q
```

홈은 데스크톱과 좁은 화면에서 확인하고, 샘플 진입 후 배치 방식·세로 이동 공간·위치 조절을 실제로 조작한다.
실제 AI 처리나 사용자 자료를 이용한 검증은 별도로 범위를 정하며, 테스트용 작업 데이터는 사용자 런타임과 분리한다.
